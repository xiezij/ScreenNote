## Context

当前应用已具备 light/dark/system 主题能力，但实际体验反馈显示两个核心问题：第一，主题切换入口在头部布局中缺乏语义归属，视觉上“插进去”的感觉明显；第二，整体样式虽去掉了紫黑渐变，但层级、留白、状态细节不够统一，导致“质感不够”和“工具感不稳”。

本次改造是二次精修，目标是让主题切换“自然地属于界面”，并让主界面在深浅主题下都呈现稳定、克制、专业的一致体验。约束为：不改业务流程、不引入新依赖、尽量保持 DOM 结构稳定以降低回归风险。

## Goals / Non-Goals

**Goals:**
- 让主题切换入口与标题/设备信息形成统一的头部工具区语义，而非单独漂浮控件。
- 建立更严格的视觉层级（页面背景 → 主面板 → 分区 → 控件）与状态一致性（hover/focus/active/disabled）。
- 优化控件比例、边框节奏、阴影密度与文本层次，提高“精致度”和“可用性”。
- 在 light/dark 主题下均保持清晰对比与稳定信息密度。

**Non-Goals:**
- 不改动录屏、截屏、保存、复制的业务行为。
- 不做大规模模板重排（例如新增侧栏或多页架构）。
- 不引入额外 UI 组件库和动画库。

## Decisions

- 决策 1：主题入口改为“头部工具项”而非独立大块标签。
  - 方案 A（采用）：放入 header actions 区并与显示器信息对齐，样式与其他工具控件统一。
  - 方案 B（未采用）：继续使用醒目 badge 样式单独展示。  
  - 理由：强调“自然可达”而不是“视觉抢占”，减少突兀感。

- 决策 2：引入双层 token 体系（基础色值 + 语义映射）。
  - 方案 A（采用）：保留当前 token 名称并补充层级 token（surface-1/2、text-1/2、border-1 等）映射。
  - 方案 B（未采用）：继续直接使用散落的 var 变量。  
  - 理由：让精修可控、减少局部修补导致的风格漂移。

- 决策 3：加强“状态一致性”作为精修优先级。
  - 方案 A（采用）：统一输入框、按钮、卡片在 hover/focus 的阴影与边框反馈节奏。
  - 方案 B（未采用）：仅调整静态配色。  
  - 理由：用户对“精致感”的核心感知来自交互状态而非静态截图。

- 决策 4：视觉方向采用“编辑器/生产力工具”范式。
  - 方案 A（采用）：中性底色、低饱和强调、窄高光边框、克制阴影。
  - 方案 B（未采用）：加重装饰背景与强动效。  
  - 理由：与当前产品定位（功能工具）更匹配，也更耐看。

## Risks / Trade-offs

- [风险] 过度克制导致界面“太平” → [缓解] 通过分区边界、间距节奏、微对比提升可扫读性。
- [风险] 精修覆盖面大，出现局部样式冲突 → [缓解] 按模块逐段替换并做 light/dark 双主题走查。
- [风险] 主题入口弱化后可发现性下降 → [缓解] 保留“主题”文字标签与明确下拉箭头反馈。
- [权衡] 不做结构重排降低了创新幅度 → [收益] 回归风险可控，交付更快。

## Migration Plan

1. 先调整头部结构与主题入口位置，完成可用性和可达性基线。
2. 按层级重构样式：页面背景与头部 → 主面板 → 分区与控件 → 反馈状态。
3. 统一按钮、输入框、卡片、toast、滚动条在两主题下的状态反馈强度。
4. 回归关键业务路径，确认功能行为不受影响。
5. 若出现视觉争议，保留 token 架构并快速调参迭代，不回退主题能力本身。

## Open Questions

- 主题入口是否需要图标化（太阳/月亮）增强识别，还是保持纯文字更克制。
- 是否增加“紧凑模式”作为后续可选项（当前先不纳入本次范围）。
