## Context

当前截图保存流程中，自动保存开关与实际行为存在偏差：用户勾选“默认文件夹自动保存”后仍可能走到保存对话框分支，违背用户预期。与此同时，界面仅展示默认目录文本，不支持直接打开目录，导致用户需要手动复制路径或自行查找文件。

本次改造需要在不影响截图主流程与现有保存能力的前提下，修复自动保存分支判断并补充目录打开交互。实现将跨越渲染层（`src/App.vue`）与 Electron 预加载/主进程桥接能力。

## Goals / Non-Goals

**Goals:**
- 自动保存开启且默认目录有效时，截图保存 MUST 直接写入目录而不弹保存框。
- 自动保存失败时提供明确错误并允许回退到手动保存。
- 默认目录文本提供可点击交互，点击后打开该目录。
- 保持原有截图、复制、录屏逻辑不变，仅修复与增强目录保存体验。

**Non-Goals:**
- 不改动录屏文件保存流程。
- 不新增目录管理页面或历史目录管理功能。
- 不引入新依赖或重构整体状态管理架构。

## Decisions

- 决策 1：自动保存使用“前置判定 + 失败回退”策略。
  - 方案 A（采用）：若 `autoSaveEnabled && defaultSaveDir` 成立，先直存；仅在写入失败时提示并回退手动保存。
  - 方案 B（未采用）：先弹框由用户确认后再保存。  
  - 理由：与“自动保存”语义一致，减少重复操作。

- 决策 2：目录打开能力通过 Electron bridge 暴露。
  - 方案 A（采用）：在 `preload` 暴露 `openPath`/`showItemInFolder` 样式 API，由渲染层调用。
  - 方案 B（未采用）：渲染层直接使用 Node API。  
  - 理由：保持进程边界清晰，符合 Electron 安全模型。

- 决策 3：目录入口用文本按钮化处理。
  - 方案 A（采用）：将“当前目录”改为可点击文本按钮，保留原信息密度并增强可用性。
  - 方案 B（未采用）：新增独立大按钮。  
  - 理由：改动小、认知负担低，不破坏现有布局。

## Risks / Trade-offs

- [风险] 目录不存在或权限不足导致直存失败 → [缓解] 捕获保存错误，提示原因并回退手动保存。
- [风险] 不同平台的目录打开行为差异 → [缓解] 使用 Electron 官方 shell API 并返回标准成功/失败结果。
- [风险] 用户误触目录链接 → [缓解] 仅在存在有效目录时可点击，并提供 hover 状态提示。

## Migration Plan

1. 修复渲染层自动保存判定与失败回退逻辑。
2. 在 preload/main 增加“打开目录”桥接 API。
3. 将默认目录文本改为可点击入口并接入新 API。
4. 回归验证自动保存与手动保存两条路径。
5. 验证目录打开成功与失败提示分支。
